#### A33a (2026-11-04): pin addendum to A33 — a shape bug fixed before any result; new code hashes

- **What happened.** The run under A33 (commit `c68a2b5`) stopped at the first box of the first video,
  with a shape error inside modelB. **No output file was written, and no name was computed**
  (`studies/d7/naming_check/run.log`).
- **The cause.** `pooled_feature` left the pooled vector as (1, 1, 768). `End2End_Model` squeezes it
  to (1, 768) before modelB (`models/end2end_model.py:253`), and A33 says "exactly as End2End_Model's
  test loop". The missing `squeeze(0)` is added; nothing else changes.
- **Why the checks missed it.** The unit test compared values with broadcasting, and the plumbing dry
  run used a dummy modelB that ignored the input's shape.
  - The test now also requires the shape (1, 768).
  - A second dry run used the **real** modelB with **random** features in place of TagCLIP's output
    (real shapes and dtype) on one HELD-A video. Its features are random, so no HELD name is
    computed.
  - It measured 0.415 s per box for modelB and 0.33 s per frame for TagCLIP alone.
- **New pins:**
  - `studies/d7/naming_check.py`: SHA256 `287099cb…4736` (was `98221359…0554`);
  - `studies/d7/tests/test_naming_check.py`: `fd554be2…b487` (was `b6a0722c…709f`).
- **Runtime estimate, revised:** about 8.7 hours. That is 59,647 boxes × 0.415 s plus 20,036 frames ×
  0.33 s.

**Not changed:** everything else in A33, including the method, the measures and the stop rule.
